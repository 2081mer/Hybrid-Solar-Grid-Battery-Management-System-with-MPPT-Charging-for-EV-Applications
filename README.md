# Hybrid Solar-Grid BMS: ESP32 Firmware

Firmware for an IoT-monitored hybrid solar-grid Battery Management System (3S Li-ion, four-switch buck-boost MPPT, ESP32, Arduino IoT Cloud).

This README explains **how to use the code**: what each file does, how to set it up, upload it, and check that it works.

---

## Files in this repository

| File | What it does |
|---|---|
| `BMS_StageG_Cloud.ino` | Main sketch. Reads the sensors, runs MPPT and protection, drives the gate drivers, relays, LCD and buzzer, and syncs data to the cloud. |
| `thingProperties.h` | Cloud variable definitions and Wi-Fi/cloud connection setup (generated by Arduino IoT Cloud). |
| `arduino_secrets.h` | Your private Wi-Fi name, Wi-Fi password and device key. **Never upload the real file to GitHub.** |
| `arduino_secrets.example.h` | Safe template to copy into `arduino_secrets.h`. |

> All three code files must be in the **same folder**, and the folder must be named `BMS_StageG_Cloud` (the same as the `.ino` file), or the Arduino IDE will not open it correctly.

---

## What you need

**Hardware**
- ESP32 development board (ESP32 Dev Module type)
- The BMS hardware wired as in the pin table below (IR2110 gate drivers + IRF540N MOSFETs, 3S Li-ion pack with protection board, relay module, DHT11, JHD-2X16-I2C LCD, buzzer with BC337 driver, voltage and current sensing)
- USB cable for programming

**Software**
- Arduino IDE 2.x
- ESP32 board package (Boards Manager: search "esp32" by Espressif Systems)
- A free Arduino IoT Cloud account: https://app.arduino.cc

**Libraries** (Library Manager; confirm against the `#include` lines at the top of the `.ino`)
- `ArduinoIoTCloud`
- `Arduino_ConnectionHandler`
- `DHT sensor library` (and `Adafruit Unified Sensor` if asked)
- `LiquidCrystal I2C`

## Step-by-step setup

### 1. Get the code
```bash
git clone https://github.com/<your-username>/<repo-name>.git
```
Or click **Code > Download ZIP** on GitHub and extract it. Open `BMS_StageG_Cloud.ino` in Arduino IDE.

### 2. Create the Thing in Arduino IoT Cloud
1. Log in to Arduino IoT Cloud and create a new **Thing**.
2. Add your ESP32 as a device (**Select Device > Set up a new device > Third-party device > ESP32**). Save the **Device ID** and **Secret Key** shown. The key is shown only once.
3. Add these five cloud variables (free plan limit is 5). Use the same names and types as in `thingProperties.h`:

| Variable | Typical type | Permission | Meaning |
|---|---|---|---|
| `soc` | Float / Int | Read only | State of charge (%) |
| `temp` | Float | Read only | Temperature (°C) |
| `iout` | Float | Read only | Battery/output current (A) |
| `vpack` | Float | Read only | Pack voltage (V) |
| `autoCharge` | Boolean | Read & Write | Dashboard switch for auto-charge |

4. In the Thing's **Network** section, enter your Wi-Fi name and password.
5. Build a **Dashboard** with a gauge/value widget for each read-only variable and a switch for `autoCharge`.

### 3. Add your secrets
1. Copy `arduino_secrets.example.h` and rename the copy to `arduino_secrets.h`.
2. Fill in your own values:

```cpp
#define SECRET_SSID "YOUR_WIFI_NAME"
#define SECRET_OPTIONAL_PASS "YOUR_WIFI_PASSWORD"
#define SECRET_DEVICE_KEY "YOUR_DEVICE_SECRET_KEY"
```
(Use the exact `#define` names that appear in your own `thingProperties.h`.)

3. Make sure `arduino_secrets.h` is listed in `.gitignore` so it is never pushed:
```
arduino_secrets.h
```

### 4. Select board and upload
1. **Tools > Board > esp32 > ESP32 Dev Module**
2. **Tools > Port** > select your ESP32's COM port
3. Click **Upload**. If it stays on "Connecting...", hold the **BOOT** button on the ESP32 until upload begins.
4. Open **Serial Monitor** (set the baud rate to the value in `Serial.begin(...)` in the sketch) to watch the startup and connection messages.

## Pin connections (as built)

| Function | ESP32 pin |
|---|---|
| IR2110 #A HIN / LIN | GPIO18 / GPIO19 |
| IR2110 #B HIN / LIN | GPIO21 / GPIO22 |
| IR2110 SD (both ICs) | GPIO23 |
| LCD SDA / SCL | GPIO16 / GPIO17 |
| Buzzer (via BC337) | GPIO4 |
| DHT11 | GPIO15 |
| Relays: solar / grid / load / emergency | GPIO25 / GPIO26 / GPIO27 / GPIO14 |
| Panel voltage | GPIO34 |
| Pack voltage (top) | GPIO35 |
| Cell tap (middle) | VP |
| Cell tap (last) | VN |
| Panel current | GPIO32 |
| Battery current | GPIO33 |

All analog inputs are on ADC1 pins, so they keep working while Wi-Fi is on.

## Safe first run (do this in order)

1. **No power stage connected.** Power the ESP32 over USB only. Confirm the Serial Monitor shows Wi-Fi and cloud connection, the LCD displays, and the dashboard values update.
2. **Check the cloud.** Toggle `autoCharge` on the dashboard and confirm the sketch reacts (Serial output or relay click).
3. **Check the gate drive without the battery.** Power the IR2110 stage from a current-limited supply, with no battery and no panel. Look at HIN/LIN and gate waveforms on an oscilloscope and confirm dead time and that high and low switches never conduct together.
4. **Add the solar panel**, then the grid source, and watch the MPPT behaviour.
5. **Connect the battery last**, through the protection board and a fuse.

## Troubleshooting

| Problem | Likely fix |
|---|---|
| Sketch won't compile: missing library | Install the library named in the error via Library Manager. |
| `arduino_secrets.h: No such file` | You haven't created it. Copy it from the example file (step 3). |
| Upload stuck at "Connecting..." | Hold BOOT during upload; check the USB cable and COM port. |
| Won't connect to Wi-Fi | ESP32 supports 2.4 GHz only. Recheck the SSID and password. |
| Cloud stays offline | Recheck Device ID and Secret Key; make sure the device is linked to the Thing. |
| LCD blank | Check SDA/SCL wiring and the I2C address (commonly 0x27 or 0x3F). |
| Readings look wrong | Recalibrate the divider ratios and current-sensor offset values in the sketch. |

## Safety

This is a prototype handling Li-ion cells and switching power. Always use the cell protection board and fusing, keep the gate drivers disabled (SD low) until PWM is valid, and never leave charging unattended during testing.
